# Hand-authored AWS resources

Repo convention: **DynamoDB table schemas and IAM policies are written by
hand**, not generated by an agent. Silent failures in schema/IAM are hard to
debug. Use this checklist when creating the production stack; keep the
resulting JSON/YAML outside AI-edited PRs or review them line-by-line.

## DynamoDB table `chat-messages`

Must match `backend/pkg/storage` (`schema.go` / `GetTableSchema`):

- Table name: `chat-messages`
- PK: `RoomID` (S)
- SK: `MessageID` (S)
- GSI `UserID-Timestamp-index`: PK `UserID` (S), SK `Timestamp` (S)
- GSI `RoomID-Timestamp-index`: PK `RoomID` (S), SK `Timestamp` (S)
- Billing: prefer **on-demand (PAY_PER_REQUEST)** in production

Create via console, CDK you own, or a reviewed CloudFormation snippet you
typed — do not paste an unverified AI schema.

## Task role IAM (minimum)

Attach to the ECS **task role** (not the execution role):

- `dynamodb:DescribeTable`, `PutItem`, `BatchWriteItem`, `Query`, `GetItem`
  on `arn:aws:dynamodb:<region>:<account>:table/chat-messages` and its indexes
- `secretsmanager:GetSecretValue` (or `ssm:GetParameter`) only for secrets
  the task actually reads, if you inject `AUTH_SECRET` / ElevenLabs that way

## Execution role IAM

Standard ECS execution role:

- Pull from ECR
- Write CloudWatch Logs to the task’s log group
- Read secrets referenced in `secrets` blocks of the task definition

## Networking extras (optional but recommended)

- VPC gateway endpoint for DynamoDB (no NAT for storage traffic)
- Security group: ALB SG → task SG `:8080`; task SG egress to HTTPS/DynamoDB
- EFS + mount point on the task if `BRIEFING_ENABLED=true` (content-hash mp3 cache)
